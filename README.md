# Coffee Shop POS System (Laravel 11)

A point-of-sale and café management system built with **Laravel 11 / PHP 8.2**. It has two interfaces:

1. **Admin / Staff panel** (`/admin/*`): for administrators, cashiers, chefs and waiters
2. **Customer panel** (`/user/*`): registered customers browse the menu, place and track orders, leave reviews and contact the shop

Based on the open-source POS by Join Coder ([@joincoder](https://www.youtube.com/@joincoder)), then customized. See [overview.md](overview.md) for the full project overview.

## Features

- Role-based access: admin, cashier, chef, waiter, user (route files in `routes/`)
- Products and categories with multiple sizes and prices per product
- Discounts (per product or across the board), taxes, delivery fees
- Order types: eat-in, take-away, delivery
- Cash, card and mobile-payment confirmation with printed payment slips. Mobile payment only shows a QR code and isn't connected to a payment gateway
- Chef/kitchen portal (branch-scoped) with KOT printing
- CRM: customer profiles, reviews, contact messages
- Suppliers and ingredient purchases; asset management (locations, categories, depreciation)
- Reports: sales, inventory, product analysis, supplier purchases, assets, feedback
- Google / GitHub OAuth login (Laravel Socialite)

## Installation & Setup

```bash
git clone https://github.com/KahafSameer/cofeesystem2.git
cd cofeesystem2

composer install
npm install

cp .env.example .env
php artisan key:generate
```

Set the database connection in `.env`. The `DB_*` lines are commented out in `.env.example`, so uncomment them:

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=coffeepos
DB_USERNAME=your_db_user
DB_PASSWORD=your_db_password
```

Create the database, then run the migrations and seed it:

```bash
php artisan migrate --seed
# Optional demo data (branches, staff users, products):
php artisan db:seed --class=DemoDataSeeder
```

## Environment Variables

All variables are listed in [.env.example](.env.example). The app-specific ones are:

| Variable | Purpose |
|---|---|
| `APP_NAME`, `APP_URL`, `APP_KEY`, `APP_TIMEZONE` | Laravel app settings (`APP_KEY` is generated by `php artisan key:generate`) |
| `DB_*` | MySQL connection |
| `MAIL_*` | Outgoing mail |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google login (Socialite) |
| `STRIPE_KEY`, `STRIPE_SECRET` | Stripe SDK keys |
| `AWS_*` | S3 file storage (optional) |

## Usage

```bash
npm run dev          # Vite dev server for assets
php artisan serve    # http://127.0.0.1:8000
```

Production assets: `npm run build`.

> ⚠️ **Testing:** `phpunit.xml` doesn't use an in-memory database, so `php artisan test` runs against your real MySQL database, and the Breeze `RegistrationTest` uses `RefreshDatabase`, which **wipes all data**. Only run targeted tests (`php artisan test --filter=...`). See [AGENTS.md](AGENTS.md).

## Deployment

`.github/workflows/deploy.yml` deploys to an EC2 server on push to `main` (or manually). It builds the frontend assets, syncs files over SSH, then runs `composer install`, `php artisan migrate --force` and the config/view caches, with maintenance mode on during the deploy.

Required GitHub Actions secrets: `EC2_HOST`, `EC2_USERNAME`, `EC2_SSH_KEY`, `EC2_HEALTH_URL`. Manual steps are in [DEPLOY_AWS_EC2.md](DEPLOY_AWS_EC2.md).
